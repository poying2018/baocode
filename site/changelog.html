Changelog

What changed in each version of BaoCode.

1.3.1

Remote projects work again

The app used to download a remote host's server from upstream's dl.baocode.dev, which never had a build of ours: a server's version is a hash of what it carries, so only the machine that made it has that one. Every SSH connection asked for a file that was not there.

  • The builds are now published in this repository's releases, named by their version, so an app built months ago still downloads the one it was built with. The first connection to a host downloads that platform's server, checks its size and SHA-256 against servers.json, and pushes it over ssh as before.
  • The installer carries the build made from these sources (Linux x64 and arm64): nothing to compile by hand.
  • Coming straight from 1.3.0+15, this also includes 1.3.0+16: BaoCode's own core reminds the model when its to-do list has gone unwritten, so the panel no longer sits still for half an hour, and such notes to the model no longer show as a tool's output.

1.3.0

A core of our own

This release replaces Claude Code's core with one written in Dart, and makes it the default: no CLI to install, with sessions, CLAUDE.md, skills, subagents and MCP servers working as before. Windows can share your own browsers too, and agents can draw on an upstream's image models. Plus the composer, the side panel, scrolling and a batch of fixes.

New

  • Our own core (Settings → General → Claude Code → Core): it runs on the upstreams of Settings → Models alone, with no Claude Code CLI on the machine. Sessions are still kept where and as the CLI keeps them, so you can switch between the two cores without losing a conversation. The built-in core uses an upstream's key; a Claude subscription's login belongs to the CLI alone, so switch back to the CLI to use one.
  • No upstream, no session: the built-in core never falls back on the CLI's setup or the machine's environment variables. Without an upstream it says so, and offers to add one or to switch back to the CLI.
  • Your browsers on Windows: the installer carries the bridge between them and the app (baocode-browser-host.exe), registers it for Chrome, Edge and Chromium, and takes it out at uninstall. The extension is unchanged.
  • Drawing: agents generate images with an upstream's image models. With no default image model it asks which to use, and a picture made with another one offers Set as default. Pictures go to the path you asked for, else to images/date/ in the data folder.
  • Polish in the composer keeps its tags, images and code, instead of flattening them to plain text.
  • The side panel moves to the conversations' left, and back.
  • New on the Stash page writes beside the cards, typed in at once, without another window.
  • A mouse wheel glides lists, trees and editors instead of stepping through them.
  • A turn under way shows its output tokens and speed live at its end.
  • The status row muses on the step just done.

Improved

  • A window closed while maximised or full screen leaves it first, with no black Space.
  • What has no room in the sidebar or Stash gives way, instead of pushing its row off screen.
  • A customize detail page's actions flush right, not halfway.
  • The built-in core's tools, results and prompts are in its own words, with the CLI's behaviour.
  • Events are logged off the drawing thread, not one disk write at a time: dragging a window and laying views out stays smooth.
  • The emoji sheets of older versions are taken out when a new one is fetched, instead of 45 MB more each time.

Fixed

  • Streamed text wrapped anew under a selection tells layout after it.
  • Live speed is right when deltas come close together.
  • Asked for a picture, an agent reaches for the image tool instead of writing about it.
  • A message's editor opened as another closes gets all its room.
  • On Windows, a diff card names its file and folder instead of showing the whole absolute path.
  • And a batch of smaller problems.

1.2.0

Meet Stash

A big release. Stash is new: jot down ideas, screenshots and links from any app, hand them to an agent when they're ready, and see how each one is going at a glance; sign in to GitHub or GitLab to import issues into it and keep issues and pull requests up to date. The phone app's beta is now on the download page. Git, the Fast IDE, remote hosts and model settings gain a good deal more, and a long list of problems is fixed.

New

  • Stash: an inbox for whatever comes to mind. Set a global shortcut in Settings → Stash and press it in any app to bring up a floating panel and note something down (none is set by default, so as not to clash with other apps). Text, screenshots, files, links, code, tables and formulas all go in, and each note has its own number, like an issue.
  • Keeping Stash tidy: pin notes, drag them into order, filter by time, project and status, and merge duplicates; search finds text inside images too, and AI search finds notes by meaning.
  • Handing a note to an agent: click Implement in BaoCode and choose a new git worktree or the current branch, or @ the note in a chat. The chat and the note are linked, and the note's card shows how the chat is going.
  • AI to say it clearly: Polish smooths the selected text, and Clarify turns a one-liner into a full request, using its images and attachments; both can be undone.
  • Accounts (Settings → Accounts): sign in to GitHub or GitLab, in the browser or with a token, GitHub Enterprise and self-hosted GitLab included. Issues and pull requests linked from Stash show their latest state and checks; import issues from your projects' repositories, and reply to or close an issue once you've confirmed, with a warning first if the text looks like it holds a local path or a secret. Tokens are kept only in this computer's keychain.
  • The phone app (beta): download it for Android or iOS from the download page, pair it with your computer, and follow and steer its agents from your phone.
  • Phones through a Cloudflare Tunnel: write the public address in Settings → Mobile as wss://your-domain, and leave the domain's Always Use HTTPS on.
  • Branch bar: the current Git branch over the chat, to search, switch and create branches; a workspace of several folders lists each folder's branch. Switching waits while an agent runs, so as not to pull the ground from under it.
  • In plan mode, the plan's card has a Start button: leave plan mode and get going on the plan in one click.
  • Each chat picks its own model; Codex's Fast tier has moved there, and both Responses and Codex upstreams support Fast.
  • Find in Chat (⌘F / Ctrl+F), and Paste as Plain Text (⇧⌘V / Ctrl+Shift+V).
  • Settings → Appearance → Interface Size scales text, icons and spacing together; the terminal's text follows it, or takes a size of its own.
  • Settings → Customize: create, edit and delete project and global rules, skills, subagents, commands, MCP servers, hooks and plugins right in the settings.
  • Custom request headers for each upstream in the model settings, with the session ID and model name available as variables.
  • Git: fetch, pull and push; pick the repository in a project with several, with submodules as repositories of their own; the graph can show every branch, names each commit's branches and tags, and lists a commit's files as a tree.
  • Files: search the whole project's text from the side panel; open a file link from a chat in the side panel, preview it or open it in the browser; Open in Terminal in the explorer, and choose which files and folders it hides in the settings.
  • Fast IDE: turn on Show agent changes as diffs to have each file an agent changes open as a diff as it goes; change a file's language mode by hand; format JSON and other files without a language server.
  • Remote hosts: the host indicator in the status bar has a menu, and files on a remote host open directly over SSH, with the ones opened lately listed.

Improved

  • The sidebar's agent list is rebuilt, with multi-selection to pin, archive and delete several at once; archived agents can show in the IDE too.
  • The Fast IDE opens in the main window by default, in place of the chat; switch back to a window per folder in the settings.
  • An earlier conversation shows that it's loading while it opens, and very long conversations run more smoothly.
  • The subagents and background tasks running show over the composer, a click away.
  • Quick Open in a remote project waits on neither the connection nor the ranking.

Fixed

  • A queued message taken back to edit lands in the composer instead of being lost, and one sent now ahead of the rest is no longer lost either.
  • A project folder that has been deleted or moved is reported in the app's language.
  • The model providers' keys come along when the data folder moves.
  • Claude Code's own models are always listed, and kept between runs.
  • A key the base URL refuses is reported, rather than left as an empty list.
  • The window buttons' place, the editor's icons, trackpad scrolling, and list selection and highlighting match the IDE's in many small ways.
  • And a batch of smaller fixes: text typed into a URL jumping about, the model's name cut short in a narrow composer, saves of one Stash note overwriting each other, and more.

1.1.0

Nice and bouncy

This release lays the groundwork for your phone: BaoCode on a phone can pair with your computer, to see and steer its agents. The conversation also has a minimap, so a long one can be taken in at a glance and any part of it reached with a click; under each reply there is now a copy button and what the turn used.

New

  • Phones (preview): a new Settings → Mobile page. Pair a phone by scanning a QR code, or let a phone on the same network find the computer; both sides show a security code to check, then they connect directly over the local network or the internet, end-to-end encrypted, and keep working when the computer's IP changes. Off until you show the QR code; the first time, macOS asks whether BaoCode may use the local network. The phone app is coming soon.
  • Conversation minimap: a miniature of the whole conversation beside it, your messages, code, tables and changes each telling apart. While you scroll, a drop of liquid glass marks where you are, magnifying what is under it a little, like the macOS Dock; click or drag it to go anywhere.
  • While the minimap shows, it takes the place of the scrollbar on the right, and the messages leave a little more room either side; in a narrow window it hides and the scrollbar is back.
  • Settings → Appearance: turn off Conversation Minimap to keep the scrollbar on the right, as before; with it on, set how opaque its glass is (0% to 150%), and how much it stretches as it follows you scrolling (Off, Subtle, Medium, Bouncy).
  • Turn footer: under a finished reply, a Copy reply button and how long the turn took; with Claude Code, also, faintly, how fast the model wrote, the tokens the turn used and what it cost; hover for the details.

Improved

  • Over a subagent's conversation, the way back reads "← Conversation", the arrow and the word one button, lit on hover or keyboard focus.
  • A running agent's loader in the sidebar is a little smaller, in keeping with the list's text.

1.0.9

Pixel loaders

A small release: a new pixel loading animation for agents and subagents, with the style and speed yours to pick, and a tidier settings window on Windows and in narrow windows.

New

  • Pixel loaders: an agent at work and a running subagent show a 3×3 pixel animation, Fill and Empty by default, slightly tinted with the theme's accent.
  • Settings → Appearance: pick the loading style for "Agent Working" and "Subagent Running" separately, from over a dozen styles (the old ring among them), and set their speed.

Improved

  • An agent whose turn is over keeps showing as running in the sidebar, the conversation list and the IDE while its background tasks (subagents, shells) are still running.
  • Subagents running in the background use the same loader as the others; Move to Background has a new icon, and background shells above the input show a terminal icon instead of a spinner.
  • On Windows, with the settings open, the header no longer shows the conversation's controls and title; the settings' page list toggle takes their place.
  • Settings pages in a narrow window have less padding on the sides, leaving the cards more room.

1.0.8

Much sharper

A wide-ranging release: import upstreams from a site in one click, manage SSH hosts from the sidebar, undo and drag files in and out of the explorer, get Claude Code downloaded for you on first use, and a batch of long-standing fixes.

New

  • One-click upstream import: click the import button on a site that offers it and, once you confirm, the upstream is added with your own key (only its name, protocol, address and key are taken). Settings → Models lists the sites officially listed at the top, those you use first; the list follows baocode.dev, with no new release needed.
  • The model picker shows each model's maker logo, and each upstream's heading has an icon. Pick one yourself (a maker's logo, the site's icon, an emoji, a built-in icon or an image you upload); unset, the maker is told from the address, or the site's icon is fetched.
  • Queued messages: what you send while the agent works no longer lands in the conversation. It waits above the input, sent in turn, and each can be taken back to edit, sent now (stopping the current task), or removed.
  • Open Project in the sidebar, and SSH hosts managed there: switch between this machine and a host, add, rename, disconnect or remove hosts. The new chat's folder menu lists SSH hosts and their projects too, and picks a folder on a host directly.
  • SSH password sign-in on Windows (OpenSSH 8.4 or newer).
  • Explorer: creating, deleting and moving files can be undone and redone (Cmd/Ctrl+Z); drag files in from other apps, or out of the window into them (a remote project's are downloaded first); copy a remote project's files to the system clipboard, and paste this machine's files into it to upload them; a folder you cannot read says so.
  • Auto save: turn on Auto Save in the File menu, or set files.autoSave (after a pause in editing, on switching editors or on leaving the window), as in VS Code.
  • The Skills page (formerly Customize) works for remote projects, managing the skills, subagents, commands, rules and MCP servers on the remote host. New ones can have Chinese names.
  • Each MCP server is checked for whether it connects: one that doesn't says why (its exit code, a timeout, a sign-in it needs) with its output log, and can be checked again, one or all.
  • Claude Code installed for you: with none on this machine, your first conversation downloads it, showing progress. By default the newest of those installed and downloaded by BaoCode is used; set a path in Settings → General to use one of your own.
  • Settings → Updates → Diagnostic Logs: when something goes wrong, upload the error logs to the developer with a note, and get a report ID back. Nothing is sent until you click Upload, and your home folder shows as ~ in the logs.
  • The settings' page list can be resized by dragging and hidden with ⌘B; in a narrow window it becomes a drawer.
  • Models that summarize their thinking, such as GPT, show a thought by its summary's title, its text when opened.
  • In the review, a changed image shows as the image, not as text.
  • Question cards can be collapsed and expanded.

Improved

  • Each model keeps its own effort and context length, and switching models no longer sends a test request first.
  • With a subagent model set, every subagent uses it (except those defined to inherit); subagents could run on the main model before.
  • Sharper text on Windows: sizes are snapped to whole pixels and text is rendered closer to Chrome.
  • Updates are checked 10 seconds after launch, then every 5 minutes, so new releases arrive sooner.
  • Model picker: a search box to click into, list edges that fade out, smoother hovering, and the context menu's colors.
  • Hovers stay within 90% of the window's width, clear of its edges.

Fixed

  • After stopping a task, tools, commands and subagents still running no longer spin forever: they show as failed (Claude Code and Codex).
  • A long conversation's scrollbar is to scale and no longer jumps as you drag it. A turn the agent takes up on its own (a background task's report, say) no longer jumps to the bottom or folds away what you are reading.
  • Tools running code --version and the like no longer open an empty BaoCode window.
  • Cancelling an SSH sign-in, or a wrong password, no longer brings the password prompt back again and again; remote projects restored at launch no longer each ask.
  • On Windows, opening the changed files of an SSH project no longer shows a grey error box.
  • On macOS, commands the agent runs can send Apple Events to other apps (e.g. with osascript); they were refused outright before.

1.0.7

The same everywhere, different everywhere

This release is mostly about polishing the interface, and adds support for VS Code theme extensions.

New

  • VS Code theme extensions: search Open VSX in the Extensions view, or drop in a .vsix file, to install its color themes and file icon themes. An extension's page shows its README, features, changelog and compatibility; you can check for updates, switch to a pre-release, enable or disable it. No extension code runs: only the themes are used.
  • The Extensions view has Themes and Language Servers tabs, and lists popular themes.
  • Pick a file icon theme with Preferences: File Icon Theme in the Command Palette, previewing each with the arrow keys. JetBrains-style icons are drawn for the light or dark theme in use.
  • New built-in themes, Bao Dark and Bao Light, now the default dark and light themes.
  • Mention files with @ in the input: pick any file or folder in the workspace, every folder of a multi-folder workspace included, or type a path starting with /, ~/ or a drive letter to complete any file on your machine (on the remote host, for a remote project).
  • Settings → Appearance → User message style: a bubble on the right (the default), or full width with the current turn's message staying at the top as you scroll.
  • Settings → Appearance → Terminal font size: follows the interface text size by default, or set it on its own.
  • Test models in Settings → Models: from a model's menu, or all of them at once (three at a time). Tests go through Claude Code itself, the way a conversation does; each shows how long it took, and on failure, the reply or error on hover.
  • ChatGPT (Codex) upstreams have a Codex version setting: the backend lists only the models that version supports, so if a new model is missing, enter a newer version and refresh the model list.
  • Fork a conversation from its menu in the sidebar to carry on from a copy of it, remote projects included.
  • Wherever a file can be revealed in Finder, it can be saved as a copy with Save As; a remote project's file is downloaded.
  • The sidebar's Archived menu adds Unarchive All and Delete All Archived.
  • In a multi-folder workspace, the agent's changes in every folder show in the review.
  • The agent is told which file is open in the editor, the cursor's line and what is selected, as Claude Code is in an IDE.
  • With no folder open, open a single file to chat with an agent about it.
  • The context usage panel adds Prompt cache: the cache hit rate of the last request and of the main conversation, with what was read, written and uncached on hover. It is not shown for third-party models that don't report their cache.
  • File icon themes can use WOFF fonts (Chalice, for one), with font icons sized as in VS Code.

Interface

  • An empty conversation shows the BaoCode logo.
  • Message bubbles and the input share one fill and border; the focused input shows a shadow instead of changing its border color.
  • With several conversations side by side, the current one has a faint outline, inset from the window's edges.
  • Conversations fade out at their top and bottom edges as they scroll.
  • Switches in Settings scale with the interface font; the active tab's top line is softer; the tab strip no longer fades at its ends.
  • The sidebar's Changes page shows the Source Control graph under the changes, both collapsible and resizable.
  • The terminal in the agent's side panel uses the editor's background, matching its surroundings.
  • The dividers between the sidebar's sections run edge to edge.
  • Settings → Updates shows this version's notes when it is the newest.

Fixed

  • The context ring updates after the context is compacted (Claude Code and Codex).
  • In SSH projects, Go to Definition opens the right file (on Windows, the path could lose its leading /).
  • Changes inside a Git repository nested in the project show in the review.
  • On Windows, typing with an input method no longer turns tags and images in the input into text.
  • A drag starting on a reply below a plan preview no longer selects the preview's hidden plan text.
  • Requests to upstreams send Claude Code's user agent, so relays such as agentrouter.org no longer answer 401 "unauthorized client detected".
  • shields.io badges in READMEs and the Markdown preview no longer show their text far too large.
  • Fixed the code area's scroll shadow turning black in some themes.
  • The first review snapshot of a project with many files no longer freezes the interface for seconds.
  • On a Chinese Windows, saving keys and running commands no longer fail when PowerShell's output isn't UTF-8.

Changed

  • Removed six themes: Monokai, Abyss, Quiet Light, Dark (Visual Studio), Dark 2026 and Light 2026. If you were using one, BaoCode switches you to Bao Dark or Bao Light.

1.0.6

New

  • Added a ChatGPT (Codex) upstream: add it in Settings → Models and sign in with your ChatGPT account to use Codex models on your subscription's quota, with no API key.
  • Add several accounts to one ChatGPT upstream and choose how requests are spread across them: Round Robin, Fill First or Most Remaining. When an account runs out of quota, requests move on to the next one automatically.
  • Settings shows each account's plan, the quota used and when it resets.
  • When an MCP server asks for information, a card now asks you: fill in its form field by field, or approve a link it wants opened (such as a sign-in page) in your browser.

Improved

  • In full access, the agent's questions and plans awaiting approval still wait for you; other permission requests are approved automatically as before.
  • If port 1455, which ChatGPT sign-in returns to, is taken by another program, sign in in the browser as usual and paste the address it ends on back into Settings.

1.0.5

New

  • Network settings let you use the system proxy, set one manually or connect directly. Test connections to several sites at once, with response times and details when a connection fails.
  • Added two built-in notification sounds: man-oh-yeah and Gulp Gulp Gulp Gulp.

Improved

  • Interface text scaling and code font size now work independently: editor and side-panel code views follow the code font size, while conversation text and interface labels follow the interface scale. Font changes apply immediately.
  • Notification sounds and previews now overlap instead of interrupting a sound already playing, on both macOS and Windows.
  • Menus keep an 8px gap from the window edges; long lists scroll within that space.

Fixed

  • Scrolling long diffs in the editor and side-panel previews stays smooth, including with many changed lines.
  • Selecting text in a conversation no longer gets disrupted when the available text widgets change.
  • Dragging across the chat-width setting no longer changes its value accidentally.

1.0.4

Improved

  • Source Control and the side panel’s Changes page no longer freeze when there are huge numbers of changes (say, a home folder made a Git repository): the first 10,000 show with a notice, file changes then no longer refresh them (Refresh does), and scrolling and dragging the scrollbar stay smooth (#6)
  • Diffs of large files, or of files changed throughout, no longer freeze the window: the diff editor, the side panel’s diff preview and inline blame compute them in the background
  • SSH remote projects get the same limit, and no longer send the whole Git status back when there are many changes
  • Language servers’ file watching skips Git’s objects and the files of packages in node_modules, and takes many changes at once a batch at a time, without slowing the window

New

  • The side panel’s Changes page finds Git repositories in subfolders, as Source Control does, and lets you switch between them

Fixed

  • An agent’s goal (/goal) was misreported: a goal given up on or ended by an error read as met, also after resuming a session; and its clock kept running when nothing worked on it
  • Dragging to select text in a conversation sometimes selected nothing until the app restarted
  • Selecting text in a conversation went wrong as a queued message was sent or the status changed
  • Anthropic-compatible endpoints (such as those of DeepSeek, Zhipu and Alibaba Cloud) now list their models

1.0.0

The first release of BaoCode: a desktop app for Claude Code, with a fast IDE built in. For macOS (Apple silicon and Intel) and Windows.

Chat

  • Steps fold into single lines, and the current task and its progress stay above the input
  • Review what Claude changed, file by file, and keep or undo it; checkpoints never touch your repository’s .git
  • Give Claude a goal with /goal, and it keeps working until the goal is met
  • A rich-text input: paste images, drop in files, and copy code from the editor as a reference to its lines
  • Edit a message you sent, search your conversations, and see your context and plan usage
  • Run several agents side by side, in tabs or in windows of their own
  • Choose how the commits and pull requests Claude writes are credited

SSH remote projects

  • Open a folder on a Linux host over SSH, as with VS Code’s Remote-SSH: the window stays on your machine, and files, search, Git, terminals, language servers and Claude Code run on the host
  • Pick a host from ~/.ssh/config, or type user@host
  • Claude Code is installed on a host that has none, and your models work there too
  • Reconnects by itself; when a host can’t be reached, you’re told why and can retry

Fast IDE

  • An editor, a terminal and Source Control with a commit graph and Git blame
  • Your VS Code themes, keybindings and language servers
  • Markdown files open as a preview you can edit in place, Typora’s way
  • Commit messages drafted by Claude Code, for you to edit and commit

Models and extensions

  • Use other models through Claude Code: Anthropic’s API, OpenAI’s Chat Completions or Responses, with API keys kept in the system keychain
  • Choose the model for each part of Claude Code’s work, and for titles and commit messages
  • Plugins, MCP servers, skills, subagents, rules, commands and hooks in one place, with your skills from claude.ai

Around the app

  • Notifications, a sound and a count on the app’s icon when an agent needs you; agents keep running in the menu bar or tray when the window is closed
  • Open a folder in BaoCode from Finder or Explorer, and keep a window on top of others
  • In English and Chinese
  • Updates itself in the background, and asks before restarting
