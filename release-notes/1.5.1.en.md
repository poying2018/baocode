Linux, and the SSH that does not need a terminal

This release brings the upstream's 1.4 and 1.5 to this repository's own line of
releases: the app now runs on Linux, and a server to work on is set up in the
app rather than in a terminal first. The updates keep coming from this
repository's releases, as they have since 1.2.0.

New
- Linux: a package for Ubuntu and other Debian-based distributions, x64 and arm64, that keeps itself up to date as the Mac and Windows apps do. It opens folders and files with the system's own dialogs, has the system's right-click menus, and pastes text, files and pictures.
- Linux updates itself: a new version is downloaded and checked as on the other systems, then installed once you enter your password, and BaoCode opens again.
- Add SSH Server: the address, the port, the user and how to sign in (a password, a private key, or Automatic, as ssh does in a terminal) are asked in the app, and a pasted user@host:port is split up for you. The keys in ~/.ssh are offered, and a password is kept in the system keychain.
- Jump hosts: a saved server can be picked to connect through, each asking for its own password.
- A server met for the first time has its key remembered by itself. One whose key changed is told as such, and its old key can be removed to connect again.
- Settings -> SSH Servers: the servers added in the app and the hosts the sidebar has used, to edit, connect, disconnect or remove.
- A core for each server: Automatic (the server's Claude Code CLI if it has one, else the built-in core), the built-in core, or the Claude Code CLI (installed there if missing). Remote hosts no longer follow this machine's core setting.
- Setting up a model: with no model to run on yet, a welcome explains what an upstream is and adds one in a click, and the conversation starts by itself as soon as a model is there.
- Agents use the user's own Chrome, through BaoCode's extension: the pages open, click and type, with the sign-ins already there, and every step of it in view in the side panel.
- DevTools' debugging for the agents: sources and breakpoints, elements, requests, site data and memory.
- Pictures show in the conversation: a tool's, and a message's own.
- Checkpoints keep only the files the agents edited, not snapshots of the whole project, and an agent's changes can be reviewed part by part beside the chat.
- A long conversation is read from its end, the earlier turns as the list is scrolled to its top; a phone may follow it so too.
- The Windows installer carries a recent OpenSSH, used where the system's is too old or missing.

Improved
- Typing in the IDE is smoother: an edit goes through only the lines it changed, the input method is given only the lines around the caret, and typing no longer redraws the whole IDE.
- Switching chat tabs in the IDE is faster: the chats seen last are kept, shown again at once where you left them.
- Changes in the side panel open in the IDE's diff editor: the deleted code in the text where it is narrow, side by side once wide enough.
- The live time, speed and tokens under a reply while the agent works are one switch now (Settings -> General).
- Through OpenCode's gateway, the requests of a conversation hit its prompt cache: faster, and cheaper.
- Long replies and thoughts let go of what is far out of view; the editors share one tokenizer, and Skia's and the image cache are kept small.
- The model menu opens scrolled to the model in use, and an upstream's models are listed by name in its settings page.

Fixed
- A picture zoomed in the preview grows over the window, not clipped to the box it first fitted to.
- Zoomed in, the window's title bar buttons are clickable to their right edge: their size rides the interface's zoom as their corner does, so a button's right no longer drags the window.
- On Windows, a language server installs with npm.cmd's own script (node running npm-cli.js), and only PATHEXT's extensions answer for a bare name on PATH: the Bash script nvm-windows keeps beside npm.cmd is no longer started as a Win32 program, which said it was not a valid Win32 application. A server started by a .cmd is killed with its tree, so its node does not go on serving under the cmd.exe that was killed.
- Another upstream picked while a turn runs takes the next message, not the process on the one before; a message sent while the agent works waits for the turn running, or joins it when set to.
- A turn stopped at the usage limit goes on once it resets, and an agent set to go on after the reset does.
- Generated images, screenshots and pictures read stay in a conversation switched away from and back to.
- Go to Definition (F12) centers its target, even one already on screen.
- A mouse wheel scrolls the conversation as Chrome does, and moves it smoothly, each notch eased over a few frames.
- A computer waking from sleep is no hang: the watchdog's clock leaves the sleep out.
- The main window opens where it was left, as big, maximized if it was.
- A NO_PROXY network is passed on to Claude Code too, and an address in one (100.64.0.0/10, Tailscale's) goes around the proxy, as curl reads it.
- Queued messages are taken up one at a time, and one sent now goes alone.
- The earlier turns come in before what is shown, which stays where it is, the spinner on till they are read.
- Back in the window after an Alt+Tab, its first key types and its frames go on, no click needed.
- A stash moved in place (an agent's write on Windows) shows without a restart, and a symbolic link is listed in the explorer as what it leads to.
