# 1.6.2

Fixed
- The tray icon was there and not there: the system took the icon and said it had not, so the app believed it had none. Closing the window hid it to the tray, but that icon was dead — clicking it did not bring the window back, and all the user saw was the app gone. The icon is now really in the tray, and clicking it brings the window back; should the tray refuse it for a while, it is put up again every few seconds until it takes.
- The window is no longer hidden when the tray icon cannot be put up: a window hidden with no icon to click is the app gone as far as the user is concerned.

Changes
- The tray icon is in the notification area, not over the taskbar (Windows 11 folds it into the hidden icons: the `^` at the right of the taskbar shows it).
- What the tray did is written to the data folder's `logs\tray.log`: when the icon cannot be found, that file says what happened to it.
- The macOS application is not built and not published any more (this fork develops the Windows version only); the remote server is still there for macOS, it runs on the SSH host.

What this fork does differently from the upstream
- Every address the app gives out is this repository's own (the repository, the releases, the issues, the website); see Settings → About.
- No usage statistics are reported and no logs are uploaded: there is no server of its own, so there is nowhere to send them.
- The diagnostics say plainly that there is no server, rather than failing quietly.
- The channel build's activation page still points at the upstream (there is no replacement).
- The featured upstreams (ymeng / ifruit) are all gone: the list is empty and those pictures are no longer published with the site.
- notanthropic.com is not given the Anthropic key.
- A stash's path cannot leave its own folder.
- A very large version number does not crash the app.
